# 按课程发布

## 本地检查

在 open-course 仓库根目录运行：

```sh
python scripts/check_catalog.py
git status --short
git diff
git diff --cached
```

检查课程顺序、链接、来源、材料许可和实际运行效果。需要修订的教学内容先完成审阅。检查器处理路径与已知模式，不能代替素材授权、事实核对或视频画面审阅。

## 公开文案

README、课程页面和下载材料应面向使用者，提供完整的课程内容与必要的使用说明。发布前清理制作过程、临时备注、调试信息和审阅对话；署名、许可、事实依据与实际能力边界应保留。中文与其他语言版本一并检查。

## 选择本次要提交的文件

只在本仓库内选择已审课程和共用工具。使用 git add 后再次看 git diff --cached，确认没有私有工程、课堂身份信息、后台配置、证书或未授权素材。提交说明应写实际课程内容与行为的改变。

## 版本与附件

每门课程在 course.json/CHANGELOG 中维护版本；通过 Git commit 固定完整状态。建议采用 `mmcool-worldview-v1.0.0`、`cool-island-v0.1.0` 等课程标签。代码工具可用独立标签；不要在仓库内为每次修订复制 v1、v2 整套目录。

视频、大型 PDF/模型和离线 ZIP 如需发布，先核对逐项许可，再使用网站或 Release 附件。只开放已有权限的部分；新闻原片或他人平台课程可提供原站入口，不能用网站曾展示过来替代再分发授权。

## GitHub 与网站分别更新

仓库更新不自动部署 aha-lab.ai；网站发布不自动开放未列出的项目源码。仓库的课程 code 目录与共用 tools 依各自许可处理。网站只部署经过审阅的站点文件，不部署仓库父目录或私有资料。

推送与网站上线分别进行。发布后核对 GitHub 的课程导航、原始文件与实际网站入口；源代码引用使用真实仓库路径和 commit，不把机构主页当作具体源文件地址。
